# ObsoleteSony CRT

Source for the ObsoleteSony CRT browser converter, based on [ntsc-rs-web](https://github.com/ntsc-rs/ntsc-rs-web). Licensed under GPL-3.0-or-later; third-party components retain their own licenses.

Build requirements: Node.js 24, Rust nightly-2026-09-05 with `rust-src`, `wasm-bindgen-cli 0.2.129`, `wasm-opt 126`, and `cargo-about 0.8.4`.

```sh
git submodule update --init --recursive
npm ci
(cd ntsc-rs-web-wrapper && bash ./build.sh)
npm run check:crt
npm run test:crt
npm run build:crt
```

Output: `package/crt-1.0.1/`. The converter's Astro integration is in `integration/astro/`; install the built runtime with `node scripts/install-site.mjs /path/to/site`.

Version 1.0.1 checks actual decoded audio before selecting a track, retains that track for export, supports local AC-3/E-AC-3 decoding when needed, and opens video at its real first presentation timestamp. Unsupported audio is explicitly labeled silent; unsupported video reports its codec and local conversion guidance. The UI layout and default effects are unchanged.

The exact shipped artifact checksums and normalized source hashes are in `releases/1.0.1/manifest.json`; `source-sync.json` checks the converter-only mirror, including Astro integration. No website artwork, unrelated archive source, or user media is included.

The locked Mediabunny 1.55.7 receives scoped Matroska CodecDelay and MP4 audio-preroll corrections during install/build. Modified MPL source is in `third_party/mediabunny/`. Compatible audio passes through with its preroll preserved and excluded from presentation by the MP4 edit list. Other decodable tracks are trimmed at sample precision and encoded to AAC with its initial padding accounted for.

AC-3 extension sources/notices/rebuild instructions are under `third_party/ac3/`. Its FFmpeg submodule is separate from the existing AAC encoder's FFmpeg pin. `package-lock.json` pins the prebuilt npm package used by the normal build; the included README explains rebuilding its embedded WASM from the pinned source.

Synthetic MKV checks (with Chrome/Edge, FFmpeg and FFprobe installed, and the integrated Astro site running at localhost:4321):

```powershell
$env:FFMPEG='path/to/ffmpeg.exe'
$env:FFPROBE='path/to/ffprobe.exe'
$env:CRT_LONG='1'
node scripts/generate-mkv-fixtures.mjs ../mkv-media
node tests/mkv-browser.mjs
node tests/mkv-lifecycle.mjs
$env:CRT_BROWSER='edge'
node tests/mkv-browser.mjs
node tests/mkv-lifecycle.mjs
node tests/mkv-verify-media.mjs
```

The optional 10-minute pulse fixture is generated by `node scripts/generate-fixtures.mjs ../implementation-media`. Set `CRT_SYNC_MP4=../implementation-media/long-sync.mp4` when running `generate-mkv-fixtures.mjs` to create `long-sync.mkv` and `ac3-sync.mkv`. `tests/long-recording.mjs` accepts `CRT_LONG_MEDIA` and `CRT_EVIDENCE`; use `../mkv-media/long-sync.mkv` and `../mkv-evidence/long`. Then run `tests/mkv-long-audio.mjs` and `tests/mkv-export-playback.mjs`. Use `CRT_CASES=ac3-sync.mkv` and distinct `CRT_REPORT_TAG` values for each browser before running `tests/mkv-reencoded-audio.mjs`. The fast `tests/mkv-preroll.mjs` checks container preservation independently of video processing.

Unsupported codecs can be converted locally, without uploading the video. For example, with FFmpeg: `ffmpeg -i input.mkv -map 0:v:0 -map 0:a:0? -c:v libx264 -pix_fmt yuv420p -crf 18 -c:a aac -b:a 192k -movflags +faststart converted.mp4`. Choose the intended audio stream using its inspected metadata. This creates a separate file; it does not modify the input.
